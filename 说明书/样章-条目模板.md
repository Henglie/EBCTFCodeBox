# op 条目标准模板 与 Rabbit 实战样章

> 本文件定义说明书中「每个 op 一条目」的标准写法，并给出一个完整样章（以 v0.1.10 的
> Rabbit 条目为例，全部内容可实机复现）。

---

## 一、条目标准模板

每个 op 条目按三级结构撰写；L1 必写，L2 默认写，高频 / 易错 op 加深 L3 精简版。

### L1 速查层（必写）

- **是什么**：一句话定位（它做什么、属于哪一类）。
- **参数表**：每个参数的名称 / 类型 / 默认值 / 取值说明（与 UI 实际一致）。
- **最小示例**：一组"输入 → 输出"（可复现）。

### L2 详解层（默认）

- **操作全流程**：从选中分类到拿到结果的完整步骤（含易错点提示）。
- **算法原理**：非数学形式讲清"它怎么工作"，配 1–2 个关键概念。
- **真题案例**：真实题目场景（来源 + 考点 + 解题步骤 + 网盘索引位）。
- **常见坑**：边界条件、方向（编码/解码）混淆、参数互斥等。

### L3 加深层（高频 / 易错 op 选配）

- 关键数学（公式仅保留理解必需部分）。
- 与同类实现的互操作说明（如与其他工具互解的条件）。
- 安全启示（何时不该用 / 有哪些攻击面）。

## 二、样章：Rabbit 流密码（现代密码·流）

> 对应 UI：左侧「现代密码·流」→ `Rabbit 流密码`。版本：v0.1.10。

### L1 速查

**是什么**：RFC 4503 定义的 Rabbit 高速流密码；用 128 位密钥（+ 可选 64 位 IV）生成
密钥流，与明文逐字节异或。加解密同一套参数，步骤可逆。

**参数表**：

| 参数（UI 名） | 类型 | 默认 | 说明 |
|---|---|---|---|
| 算法变体 | 下拉 | CryptoJS Legacy | 三档：`CryptoJS Legacy`（旧版在线工具默认，推荐）/ `CryptoJS 标准` / `RFC 4503 文档方向`（0.1.9 及更早行为） |
| 密钥 / 口令 | 文本 | 空 | 填 **32 位 hex** = 密钥直用；填其他内容（或留空）= CryptoJS 口令封装模式 |
| IV | 文本 | 空 | 仅密钥模式使用（16 位 hex）；留空 = 无 IV |
| 口令爆破候选 | 多行文本 | 空 | 每行一条；输入为 CryptoJS 密文未直接命中时，连同内置常见口令逐条尝试，只列可读结果 |

**最小示例（密钥模式）**：

```
输入：Hello
参数：变体=Legacy，密钥=00000000000000000000000000000000，IV 留空
点「编码」→ 输出：A5D2690B58（小写口径 a5d2690b58）
```

### L2 详解

**操作全流程 · 场景一（题目给了 key/iv）**
1. 左侧选「现代密码·流」→ Rabbit 流密码；
2. 密钥填 32 位 hex、IV 填 16 位 hex（题目没给 IV 就留空，不要乱填零）；
3. 密文粘贴到输入区 → 点「解码」；得到明文后如乱码，**换一档变体再试**（见下）。

**操作全流程 · 场景二（只给一串 base64 密文，最常见）**
1. 密文粘贴到输入区（形如 `U2FsdGVkX1...`）；
2. 密钥框**留空**先试；
3. 点「解码」：
   - 命中空口令 → 直接输出明文；
   - 未命中 → 自动用内置常见口令逐个尝试，列出可读命中（标注口令与变体）；
4. 若都不中，把你知道的候选口令逐行填进「口令爆破候选」再解。

**算法原理（一句话版）**：8 个 32 位状态字 + 8 个计数器 + 1 位进位，靠着"平方取中异或"
（g 函数）与旋转加法推进 128 位状态；密钥/IV 装载后先空转若干轮，之后每轮吐 16 字节密钥流。
细节：装载 4 轮 → 计数器交叉异或 → 再 4 轮（有 IV 时），输出与明文异或。

**变体为什么要三档**：不同工具链对"密钥/IV 字节串如何装入状态"的约定不同——CryptoJS
（网页工具的绝对主流）与 RFC 文档的字节方向是两套。经与 crypto-js 逐字节对拍，三档换算
只是**纯输入重排**、不影响安全性，但**决定能不能和其他工具互解**：

| 变体 | 谁在用 | 说明 |
|---|---|---|
| CryptoJS Legacy | 旧版在线工具、旧版 CryptoJS、多数 CTF 出题脚本 | **默认档**；遇到 U2FsdGVkX1 开头先试它 |
| CryptoJS 标准 | 新版 CryptoJS | 同上但按标准字节方向 |
| RFC 4503 文档方向 | 学术对照 / 0.1.9 及更早版本 | 与 RFC 附录调试向量的状态数值一致 |

**真题案例（真实，2026-10）**：社区反馈题目密文
`U2FsdGVkX1/+ydnDPowGbjjJXhZxm2MP2AgI`，旧版在线工具可解出、本工具旧版解不开。
定位：密文为 CryptoJS 口令封装（base64 的 `Salted__` 格式），算法用的是 **RabbitLegacy**。
v0.1.10 后操作：把密文粘进输入区，**什么都不用填**（口令留空）点解码 → 直接得到
`Cute_Rabbit`。（原始反馈见附录真题索引。）

**常见坑**：
- `U2FsdGVkX1` 开头 = base64 的 "Salted__"，是**口令封装**（口令走 MD5 派生），不是 hex 密文；
- 密钥框填了 16/24 位等"半个 hex"会当**口令**处理（非 32 位 hex 一律按口令），别混淆；
- 变体错了会得到"像随机的字节"而非报错——先用爆破试两档再怀疑密钥；
- RFC 文档方向档输出与 RFC 附录打印相差 16 字节块反转，属文档打印约定差异，不是 bug。

### L3 精选（互操作说明）

- 与其他工具互解条件：算法变体 + 字节方向一致 + 口令 KDF（EVP_BytesToKey，MD5）一致；
  本工具的口令封装严格复刻 CryptoJS（随机盐每次不同，密文不可逐字节比对，能解即通）。
- 密钥模式口诀：**对拍看输出，不要看解释**——同一 key/iv，"两档各试一次"是现场最快的判断法。
