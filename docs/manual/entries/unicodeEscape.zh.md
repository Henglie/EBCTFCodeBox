# Unicode 转义

> 对应 UI：左侧「文本 / 传输编码」→ `Unicode 转义`。所属：文本传输编码族。

## L1 速查

**是什么**：把字符写成 `\uXXXX` 或 `U+XXXX` 这类转义形式。JS/JSON 源码、被混淆的字符串里常见。

**参数表**：

| 参数（UI 名） | 类型 | 默认 | 取值说明 |
|---|---|---|---|
| 格式 | 下拉 | `uXXXX` | `uXXXX` / `U+XXXX` / `&#xXXXX;` 等写法 |
| 全部转义 | 开关 | 开 | 开=每个字符都转义；关=只转非 ASCII |
| 补齐位数 | 数字 | 4 | 十六进制最少位数（BMP 内为 4） |
| 大写十六进制 | 开关 | 开 | `\u0041` vs `\u0041` 的大小写 |

**最小示例**：

```
输入：AB
参数：默认（uXXXX，全部转义，4 位，大写）
点「编码」→ 输出：\u0041\u0042
```

## L2 详解

**操作全流程**：
1. 左侧「文本 / 传输编码」→ `Unicode 转义`；
2. 粘 `\uXXXX` 文本点「解码」；
3. 编码时按目标语言选格式：JS/JSON 用 `uXXXX`；文档标注用 `U+XXXX`；HTML 场景用 `&#xXXXX;`。

**算法原理**：每个字符取它的 Unicode 码点，写成固定位数的十六进制。BMP（U+0000–U+FFFF）用 4 位；超出 BMP 的字符（如 emoji）在 JS 里要用代理对（两个 `\u`）表示。

**常见坑**：
1. **BMP 外字符是代理对不是单个 `\u`**：`😀`（U+1F600）在 JS 里写成 `\uD83D\uDE00` 两个单元，逐个 `\u` 解码再拼回来才对，直接按"一个 `\u` 一个字符"处理会得到乱码。
2. **`\u` 是 4 位定长，`\x` 是 2 位字节**：`\x41` 是字节转义（只能表示 0–255），`\u0041` 是字符转义。混用会得到不同结果。
3. **大小写与位数影响字符串比对**：`\u0041` 与 `\u41` 在有些解析器里等价、有些不等价；做精确匹配时先统一成 4 位大写。
4. **不是所有 `\u` 都来自 Unicode 转义**：正则里的 `\u` 是转义语法，某些语言源码里的 `\u` 还会在词法阶段就被处理，语义与运行时不同。
