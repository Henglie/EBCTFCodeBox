# StegSolve · 全帧导出

> 对应 UI：`StegSolve` 工具栏「批量导出帧 / 通道」，或总览对话框里的「导出全部 ZIP」。所属：集合工具 · 导出子功能。

## L1 速查

**是什么**：把**全部动画帧**、**首帧的 42 个通道变换**和一份 `manifest.txt` 打成一个 ZIP 下载。产物是**一个 zip**（不是散图），文件名 `<原文件名去扩展名>_stegsolve_frames_channels.zip`，MIME `application/zip`。

**参数表**：

| 参数（UI 名） | 类型 | 默认 | 取值说明 |
|---|---|---|---|
| 入口 A：工具栏「批量导出帧 / 通道」 | 按钮 | — | 未载入图像时禁用 |
| 入口 B：总览「导出全部 ZIP」 | 按钮 | — | 与入口 A 调用同一函数，产物与命名相同 |
| 导出范围 | 固定 | 全部帧 | 与当前选中帧无关，永远导出全部帧 |
| 体积上限 | 常量 | 256 MiB | 累计超过即中止，整包不落盘（不留半包） |
| 并发保护 | 固定 | 单飞 | 导出中重复点击被忽略 |

**ZIP 结构**（4 帧图为例，共 47 条）：

| 顺序 | 条目 | 说明 |
|---|---|---|
| 1..N | `frames/frame_001.png`、`frames/frame_002.png`… | 第 1..N 帧，整幅、RGBA 8bit，序号 3 位补零 |
| N+1..N+42 | `channels/01_原图.png` … `channels/42_灰度位_(R=G=B).png` | 首帧的 42 个变换，序号 2 位补零，标签里的空格/符号转下划线 |
| 最后 | `manifest.txt` | 来源 / 格式 / 尺寸 / 帧数 / 通道数 / 生成时间 + 46 行文件清单 |

**最小示例**：

```
输入：anim4.png（APNG，4 帧，4×3）
操作：点「批量导出帧 / 通道」
产物：anim4_stegsolve_frames_channels.zip（12520 B，47 条）
首条：frames/frame_001.png；末条：manifest.txt
```

## L2 详解

**操作全流程**：
1. 载入图像（单帧 PNG 也可以，得到 1 帧 + 42 通道）；
2. 点工具栏「批量导出帧 / 通道」，或开总览点「导出全部 ZIP」；
3. 状态栏显示进度 `正在导出 i/47…`，结束后显示 `已导出 4 帧 + 42 通道（12 KiB）`；
4. 解包核对：先数条目（N + 42 + 1），再按上面的顺序核名，最后抽查像素。

**算法原理**：先按帧序逐帧编码 PNG（浏览器有 `CompressionStream` 时用真实 deflate，没有就退回 stored 块），再按「帧 → 通道 → manifest」的顺序写入一个 STORE（不压缩）方式的 zip；条目标志位对非 ASCII 名写 UTF-8 位，超出 65535 条或 32 位长度字段时会直接报错而不是写 ZIP64。通道部分始终取首帧，所以「多帧图」的通道结论只有一份。

**实测证据**（4 帧 4×3 动图）：
- 两个入口各触发一次，`suggestedFilename` 都是 `anim4_stegsolve_frames_channels.zip`，产品 Blob 的 MIME 为 `application/zip`；
- 条目 47 条，顺序与上表完全一致；`frames/*.png` 4 张逐像素等于夹具 4 帧；
- `channels/01_原图.png` 等于首帧；`channels/02_颜色反转_(XOR).png` 等于 RGB 取反且 alpha=255；`channels/36_完整_Red.png` 等于 `(R,0,0,255)`；
- 42 个通道条目全部可独立解码为 4×3 RGBA（colorType 6）；
- `manifest.txt` 46 行清单，含 `来源: anim4.png`、`格式: APNG`、`尺寸: 4×3`、`帧数: 4`、`通道变换: 42（基于首帧）`；
- 先在选中第 3 帧时导出、再在选中第 2 帧时导出，两次的 `frames/*.png` **逐字节相同**（整包差异只在 manifest 的生成时间）。

**常见坑**：
1. **不是「只导选中帧」**：选中哪一帧都不影响范围；要单帧请用「保存当前帧」，它才跟着选中帧走。
2. **命名口径两套**：zip 名**剥掉**扩展名（`anim4.png` → `anim4_stegsolve_...zip`），单帧保存**保留**扩展名（`anim4.png_frame3.png`）。写脚本批量处理时别按同一规则套。
3. **通道名被净化**：空格与 `\ / : * ? " < > |` 全部转成 `_`，首尾下划线会去掉，所以是 `颜色反转_(XOR).png`、`完整_Alpha.png`，不是原标签。
4. **两次导出不会逐字节相同**：manifest 带生成时间；要判断「内容是否一致」得比帧与通道条目，不能比整包哈希。
5. **单帧图的条数是 44 不是 47**：1 帧 + 42 通道 + manifest。
6. **超限是中止不是截断**：累计体积超过 256 MiB 会抛错，一个文件都不下载；此时应减少帧数或改用单帧保存。
7. **通道永远基于首帧**：多帧图不会给你「第 2 帧的 42 个通道」。

| 操作 | 输入 | 参数 | 产物 |

| 多帧导出 | 4 帧 APNG（4×3） | 默认 | 47 条 / 12520 B |
