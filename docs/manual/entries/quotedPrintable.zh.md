# Quoted-Printable

> 对应 UI：左侧「文本 / 传输编码」→ `Quoted-Printable`。所属：文本传输编码族。

## L1 速查

**是什么**：邮件里用的编码（RFC 2045）：把非 ASCII 字节写成 `=XX`，行太长用行尾 `=` 做软换行。看到满屏 `=XX` 想到它。

**参数表**：无参数（编码/解码全自动）。

**最小示例**：

```
输入：你好
点「编码」→ 输出：=E4=BD=A0=E5=A5=BD
```

## L2 详解

**操作全流程**：
1. 左侧「文本 / 传输编码」→ `Quoted-Printable`；
2. 粘 QP 文本点「解码」；编码方向把原文转 QP；
3. 若结果里有大量 `=E4=BD=A0` 这类连续三字节组，说明原文是 UTF-8 中文。

**算法原理**：可打印 ASCII（33–126，以及空格和制表符在行内时）原样保留，其余字节写成 `=` 加两位大写十六进制；`=` 自身写成 `=3D`。每行不超过 76 字符，超长时在行尾放一个 `=` 表示"下一行接着读"（软换行）。

**常见坑**：
1. **行尾 `=` 不是数据**：它是软换行标记，解码时必须与下一行拼接；把行尾 `=` 当成 `=3D` 去解会多出字节。
2. **`=` 本身必须写成 `=3D`**：原文里的等号如果不转义，解码器会把它当成转义引导符，后面的字符被吃掉。
3. **行尾空格要写成 `=20`**：SMTP 可能在传输中剥掉行尾空白，所以标准要求把行尾空格显式转义。
4. **与 URL 编码像但前缀不同**：QP 用 `=`，URL 用 `%`。`=E4=BD=A0` 是 QP，`%E4%BD%A0` 是 URL 编码，别互相套。

**真题案例**：暂无已核实案例。

## 更多示例

| 方向 | 输入 | 参数 | 输出 |
|---|---|---|---|
| 解码（文本） | `=E4=BD=A0=E5=A5=BD` | 默认 | `你好` |
