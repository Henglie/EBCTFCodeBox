# Base85 / Ascii85

> 对应 UI：左侧「Base 编码」→ `Base85 / Ascii85`。所属：Base 编码族。

## L1 速查

**是什么**：密度比 Base64 更高的编码，每 4 字节用 5 个字符表示。Adobe 的 Ascii85（常见 `<~ ~>` 包裹）和 ZeroMQ 的 Z85 都是它的变体。

**参数表**：

| 参数（UI 名） | 类型 | 默认 | 取值说明 |
|---|---|---|---|
| 字母表 | 下拉 | `Standard` | `Standard`（Adobe Ascii85）/ `Z85`（ZeroMQ）/ `IPv6`（RFC 1924） |
| Custom Alphabet（85 字符，留空=用上方 preset） | 文本 | 空 | 85 个互不重复字符 |
| 兼容模式（输出不带 `<~ ~>` 包裹） | 开关 | 关 | 关闭包裹 |
| 输出 `<~ ~>` 包裹（Standard 生效） | 开关 | 开 | 输出的首尾标记 |
| 全零组字符（Standard） | 文本 | `z` | 4 字节全零压缩成这个字符 |
| 解码时移除非字母表字符 | 开关 | 关 | 剥掉空白等 |

**最小示例**：

```
输入：Hello
参数：Standard（默认，带 <~ ~>）
点「编码」→ 输出：<~87cURDZ~>
```

## L2 详解

**操作全流程**：
1. 左侧「Base 编码」→ `Base85 / Ascii85`；
2. 看到首尾有 `<~` `~>` 就是 Adobe Ascii85，直接解码；
3. 没有包裹符时先试「兼容模式」，仍乱码就换 `Z85` / `IPv6` 档——这三套字母表互不通用。

**算法原理**：每 4 字节（32 位）当成一个无符号整数，转成 5 位 85 进制（85⁵ > 2³²，够用）。Adobe 版把 4 字节全零压缩成一个 `z`，并用 `<~ ~>` 标示边界；Z85 不压缩、不包裹，只换字母表。

**常见坑**：
1. **`<~ ~>` 是标记不是数据**：解码时若没开「移除」或包裹识别，`<~` 会被当成普通字符参与运算，结果整体错位。
2. **全零组压缩成 `z` 是 Adobe 特权**：Z85 没有这个规则，同一段零字节在两档下长度不同，不能互换。
3. **输入长度必须是 4 的倍数**：Ascii85 按 4 字节分组，末尾不足 4 字节要用特殊规则补齐；直接喂 3 字节会得到与标准工具不同的结果。
4. **Z85 的字母表把 `#` `@` `%` `$` 放在末尾**：与 Ascii85 的 `!`~`u` 连续区间完全不同，肉眼判断"像不像 Base85"没用，得试。
