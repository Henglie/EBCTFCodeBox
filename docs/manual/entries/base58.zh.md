# Base58

> 对应 UI：左侧「Base 编码」→ `Base58`。所属：Base 编码族。

## L1 速查

**是什么**：去掉形近字符（`0` `O` `I` `l`）的进制编码，比特币地址与短链常用。整串字节当作一个大整数，反复除以 58 取余。

**参数表**：

| 参数（UI 名） | 类型 | 默认 | 取值说明 |
|---|---|---|---|
| 字母表 | 下拉 | `bitcoin` | `bitcoin` / `flickr`（小写在前）/ `ripple`（XRP 乱序）/ `custom`（用下方码表） |
| 解码时移除非字母表字符 | 开关 | 关 | 剥掉空白等 |
| 自定义码表（alphabet=custom 时生效） | 文本 | Bitcoin 表 | 58 个互不重复字符 |

**最小示例**：

```
输入：hello world
参数：bitcoin（默认）
点「编码」→ 输出：StV1DL6CwTryKyV
```

## L2 详解

**操作全流程**：
1. 左侧「Base 编码」→ `Base58`；
2. 默认 bitcoin 字母表，直接粘串点「解码」；
3. 解出乱码先换字母表（Flickr 把大小写顺序改了，Ripple 又是另一套乱序），三种都试一遍成本很低。

**算法原理**：把整段字节看成一个 256 进制大整数，不断除以 58，余数查 58 字符表，最后把余数倒序拼起来。开头的零字节不做除法，直接映射成若干个 `1`（bitcoin 表首字符）。

**常见坑**：
1. **没有 `0` `O` `I` `l`**：这四个字符在 Base58 里不存在，串里出现它们说明不是 Base58，或者已经被人工抄错。
2. **字母表有三套且互不兼容**：bitcoin / flickr / ripple 的字符顺序不同，同一串换表解码结果完全不同，且都不会报错——只会给你一串"看起来像乱码"的字节。
3. **前导零的处理**：字节流开头的 `0x00` 会变成开头的 `1`，解码时要还原成 `0x00`；如果你手工去掉了这些 `1`，数据就短了。
4. **Base58Check 不是 Base58**：比特币地址末尾 4 字节是双 SHA-256 校验和，直接当 Base58 解会多出 4 字节"尾巴"。
