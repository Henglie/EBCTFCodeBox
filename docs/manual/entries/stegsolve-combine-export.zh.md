# StegSolve · 多图合并导出

> 对应 UI：`StegSolve` → 「图像合并」页签。所属：集合工具 · 合并子功能。

## L1 速查

**是什么**：把当前图和另一张图按 13 种算法合成为一张新图并导出 PNG。尺寸不一致时**不是报错**：非交织模式把画布补到两图最大宽高（越界像素按 0 参与运算），交织模式先裁到两图公共最小宽高再扩展画布。

**参数表**：

| 参数（UI 名） | 类型 | 默认 | 取值说明 |
|---|---|---|---|
| 选择第二张图 | 文件 | 未选 | 只取该图的**第 1 帧**参与合并 |
| 合并方式 | 下拉 0–12 | 0 = XOR | `XOR`/`OR`/`AND`/`ADD`/`ADD (R,G,B separate)`/`SUB`/`SUB (R,G,B separate)`/`MUL`/`MUL (R,G,B separate)`/`Lightest`/`Darkest`/`Horizontal Interlace`/`Vertical Interlace` |
| 尺寸/方式标签 | 文本 | — | 形如 `4×3 · XOR`，显示**产物**宽高 |
| 保存合并结果 | 按钮 | 禁用至有结果 | 文件名 `<主图名>_combine<模式号>.png`，PNG / RGBA |

**最小示例**：

```
输入：pair_same_a.png（4×3） + pair_same_b.png（4×3），方式 = XOR
首像素：(1,2,3) XOR (255,254,253) = (254,252,254)
产物：pair_same_a.png_combine0.png，4×3，MIME image/png
```

## L2 详解

**操作全流程**：
1. 先打开主图，切「图像合并」；
2. 点「选择第二张图」载入另一张（解码失败会报错并停在“无结果”状态）；
3. 选合并方式，预览与标签立即刷新为 `产物宽×高 · 方式`；
4. 点「保存合并结果」导出 PNG；
5. 异尺寸时看标签确认产物尺寸，再决定要不要用交织模式。

**算法原理**：
- 非交织（0–10）：画布取 `max(宽)` × `max(高)`；对每个坐标，越界的一侧按像素 `0` 处理，所以小图外的区域等于「大图像素与 0 运算」；
- 3/5/7 是**打包 24 位整体**加减乘（有跨通道进位），4/6/8/9/10 是**逐通道**运算，两者结果不同；
- 11/12：先取 `min(宽)` × `min(高)`，再按行（11）或按列（12）交替拼接，产物尺寸翻倍；
- 参与运算的只有 R/G/B，**输出 alpha 恒为 255**，输入透明度被丢弃。

**实测证据**（同尺寸 4×3 一对、异尺寸 4×3 + 2×2 一对）：
- 13 种方式在两组夹具上全部逐像素对拍通过（含 24 位整体加减乘与逐通道版本的差异）；
- 同尺寸 XOR 首像素 `(254,252,254,255)`，与手算一致；
- 异尺寸 XOR：产物 `4×3`，`(0,0)` = `(194,112,44)`（两图异或），`(2,0)` = `(70,80,90)`（第二张图越界，按 0 处理 → 只剩主图）；
- 异尺寸 + `Horizontal Interlace` → `2×4`；`Vertical Interlace` → `4×2`（都先裁到 2×2）；
- 产物 PNG 全部为 4×3 / 2×4 / 4×2 RGBA 8bit，MIME `image/png`。

**常见坑**：
1. **只取第二张图的第 1 帧**：拿动图当第二张时，用的是它的首帧，不是当前显示帧。
2. **换图不重置方式**：载入新主图后，合并方式仍是上次选的那一项；看到 `4×3 · ADD (R,G,B separate)` 别以为默认是 XOR。
3. **交织是裁剪，不是补 0**：`4×3 + 2×2` 的交织产物只有 `2×4` 或 `4×2`，右边/下边的像素被直接丢掉；要保留全幅请用非交织。
4. **名称指交织轴，不宜用来猜画布尺寸**：选「Horizontal Interlace」时逐行交织，得到 `2×4`；选「Vertical Interlace」时逐列交织，得到 `4×2`。请以预览显示的尺寸为准。
5. **alpha 被丢弃**：输入带透明像素时，合并结果一律不透明；不要用合并结果判断透明度通道。
6. **同名覆盖**：文件名只由「主图名 + 模式号」决定，同一参数连存两次得到同一个名字，产品不追加 `(1)` 之类后缀，落盘是否覆盖由浏览器/保存位置决定。
7. **尺寸不一致在这里不是错误**：旧核心的同名 `combineImages` 接口会抛「尺寸不一致」，本页用的是另一套允许补 0 的实现，别把两者的行为混着写。

## 更多示例

| 操作 | 输入 | 参数 | 产物 |
|---|---|---|---|
| 同尺寸异或 | 4×3 + 4×3 | XOR（默认） | `pair_same_a.png_combine0.png`，4×3 |
| 逐通道相加 | 同上 | ADD (R,G,B separate) | `pair_same_a.png_combine4.png`，4×3 |
| 异尺寸异或 | 4×3 + 2×2 | XOR | `pair_diff_a.png_combine0.png`，4×3（补 0） |
| 异尺寸交织 | 4×3 + 2×2 | Horizontal Interlace | `pair_diff_a.png_combine11.png`，2×4（裁剪后翻倍） |
| 异尺寸交织 | 4×3 + 2×2 | Vertical Interlace | `pair_diff_a.png_combine12.png`，4×2 |
