# Base32

> 对应 UI：左侧「Base 编码」→ `Base32`。所属：Base 编码族。

## L1 速查

**是什么**：用 32 个字符（默认 `A-Z` 加 `2-7`）表示字节的编码。比 Base64 长，但只用大写字母和少量数字，肉眼不容易认错字。

**参数表**：

| 参数（UI 名） | 类型 | 默认 | 取值说明 |
|---|---|---|---|
| 变体 | 下拉 | `rfc4648` | `rfc4648`（A-Z2-7，带 pad）/ `hex`（0-9A-V，带 pad）/ `crockford`（去 ILOU，容错，无 pad）/ `zbase32`（小写，无 pad） |
| 补 =（仅 rfc4648/hex） | 开关 | 开 | 关闭后末尾不写 `=` |
| 解码时移除非字母表字符 | 开关 | 关 | 剥掉空白等 |
| 自定义码表（覆盖变体字母表） | 文本 | 空 | 填了就用它，长度须 32 |

**最小示例**：

```
输入：abc
参数：默认（rfc4648，补 =）
点「编码」→ 输出：MFRGG===
```

## L2 详解

**操作全流程**：
1. 左侧「Base 编码」→ `Base32`；
2. 粘 Base32 串点「解码」；编码方向把原文转 Base32；
3. 先判断变体：全大写且只含 `A-Z2-7` → rfc4648；含 `0-9A-V` → hex；含 `0-9A-HJKMNP-TV-Z` 且没有 `=` → Crockford；全小写 → zbase32。

**算法原理**：每 5 字节（40 位）切成 8 组、每组 5 位，5 位值（0–31）查 32 字符表。不足 5 字节时补 0 位并用 `=` 补齐，所以长度是 8 的倍数，末尾 `=` 只有 1/3/4/6 个这几种。

**常见坑**：
1. **标准 Base32 里没有 `0` `1` `8` `9`**：看到这四个数字就别按 rfc4648 解，多半是 base32hex 或别的编码。
2. **Crockford 与 rfc4648 字母表不同**：Crockford 去掉了 `I` `L` `O` `U`（并把 `O`→`0`、`I/L`→`1` 做容错），同一串用错变体会整体错位，不是个别字符错。
3. **`=` 的个数是 1/3/4/6，不是任意值**：长度必须是 8 的倍数；如果长度对不上，先检查是不是复制时丢了尾部 `=`。
4. **base32hex 与标准只差字母表排列**：`hex` 档是 `0-9A-V`，与标准的 `A-Z2-7` 完全不同序，肉眼极像，解出乱码先换这一档。
