# URL 编码（百分号编码）

> 对应 UI：左侧「文本 / 传输编码」→ `URL 编码`。所属：文本传输编码族。

## L1 速查

**是什么**：把 URL 里不能直接出现的字符写成 `%` 加两位十六进制的编码，RFC 3986 定义。Web 题里满屏 `%XX` 基本就是它。

**参数表**：

| 参数（UI 名） | 类型 | 默认 | 取值说明 |
|---|---|---|---|
| 模式 | 下拉 | `standard` | `standard`（对齐 encodeURIComponent，不编码 `!*'()`）/ `full`（`!*'()` 也编码）/ `plus`（空格→`+`，`!*'()` 编码） |

**最小示例**：

```
输入：a b&c
参数：standard（默认）
点「编码」→ 输出：a%20b%26c
```

## L2 详解

**操作全流程**：
1. 左侧「文本 / 传输编码」→ `URL 编码`；
2. 粘含 `%XX` 的串点「解码」；
3. 编码时按场景选模式：普通参数用 `standard`；要严格全转义用 `full`；表单提交（`application/x-www-form-urlencoded`）用 `plus`。

**算法原理**：先把文本按 UTF-8 转成字节，再逐字节判断——属于 URL 安全字符的原样保留，其余写成 `%` 加该字节的两位大写十六进制。所以中文一个字会变成 3 个 `%XX`（UTF-8 三字节）。

**常见坑**：
1. **三种模式对 `!*'()` 的处理不同**：`standard` 保留它们（对齐浏览器 `encodeURIComponent`），`full` 全编码。同一串在两种模式下输出不同，但解出来一样——比较"是否与标准工具一致"时必须先对齐模式。
2. **空格有两种写法**：路径/普通场景是 `%20`，表单查询串里是 `+`。解码时 `plus` 模式才把 `+` 还原成空格，其他模式会把 `+` 当字面加号。
3. **中文是 UTF-8 三字节不是 Latin-1 单字节**：`你` = `%E4%BD%A0`。若拿到 `%C4%E3` 这种两字节形式，那是 GBK 编码，需要先按 GBK 解字节再转文本。
4. **双重编码**：`%` 自身被编码成 `%25`，所以 `%2520` 解一次是 `%20`，解两次才是空格。CTF 里常故意套两层。

## 更多示例
