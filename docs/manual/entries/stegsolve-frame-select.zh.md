# StegSolve · 帧选中

> 对应 UI：左侧「文件隐写」→ `StegSolve` → 「帧浏览」页签。所属：集合工具 · 帧浏览子功能。

## L1 速查

**是什么**：在多帧图像（APNG / GIF）里逐帧定位、查看与保存**单帧**。它只改变「当前看第几帧」和「保存哪一帧」，不改变批量导出的范围（批量导出永远导出全部帧，见《StegSolve · 全帧导出》）。

**参数表**：

| 参数（UI 名） | 类型 | 默认 | 取值说明 |
|---|---|---|---|
| 上一帧 / 下一帧 | 按钮 | — | 索引 −1 / +1，两端取模回绕（1 的上一帧是最后一帧） |
| 帧计数标签 | 文本 | `- / -` | 形如 `3 / 4 · 4×3`：当前帧序号 / 总帧数 · 画布尺寸；序号从 1 起显示 |
| 保存当前帧 | 按钮 | — | 把当前帧整幅存成 PNG；文件名 = 原文件名（含扩展名）+ `_frame<序号>` + `.png` |

**最小示例**：

```
输入：anim4.png（APNG，4 帧，4×3）
操作：帧浏览 → 点两次「下一帧」
标签：3 / 4 · 4×3
点「保存当前帧」→ 产物：anim4.png_frame3.png（1 个子图，尺寸 4×3，RGBA 8bit）
```

## L2 详解

**操作全流程**：
1. 打开一张多帧图，切到「帧浏览」；标题右侧显示 `APNG · 4×3 · 4 帧` 这类元信息；
2. 用「上一帧 / 下一帧」定位，标签实时更新为 `当前 / 总数 · 宽×高`；
3. 需要单帧时点「保存当前帧」，得到一张 PNG；
4. 想确认某一帧是不是载荷所在，先记住帧序号，再对照「帧 / 通道总览」里的「动画帧」页签。

**算法原理**：解码器把每一帧**合成为完整画布**后留存（GIF 会执行 disposal 清区/还原，APNG 会按 dispose 与 blend 叠加），因此第 N 帧保存下来的是「此刻屏幕上看到的那一幅」，不是文件里那段局部更新矩形。帧索引内部从 0 起、界面显示从 1 起，切换用取模回绕。

**实测证据**（4 帧 4×3 动图）：
- 连点下一帧的标签序列：`1 / 4` → `2 / 4` → `3 / 4`；再连点三次上一帧：`4 / 4`（回绕），继续正向到 `1 / 4`（再次回绕）；
- 第 3 帧保存物逐像素等于夹具第 3 帧手写 RGBA；第 4 帧同理；
- 单帧 PNG 也进本页，标签为 `1 / 1 · 4×3`。

**常见坑**：
1. **文件名保留原扩展名**：对 `anim4.png` 保存第 3 帧得到 `anim4.png_frame3.png`，不是 `anim4_frame3.png`。同一目录连存多张时肉眼容易看成一类文件，脚本匹配要按 `<原名>_frame<N>.png`。
2. **方向键切的是主视图变换，不是帧**：帧浏览面板的提示写「←/→ 切换帧」，但实测按 → 只把主视图变换从 `1 / 42` 推到 `2 / 42`，帧标签停在 `1 / 4`。切帧必须点按钮（已记为缺陷候选，正文按实测行为写）。
3. **0 帧容器打不开**：只有文件头、逻辑屏描述符和 trailer 的 GIF 会报「打开失败：GIF 未包含可解码帧」，总览/导出按钮保持禁用；此时标题与元信息仍是上一张图（不会清空），不要拿标题判断这次载入成功。
4. **帧数决定总览默认页**：帧数 > 1 时总览默认落在「动画帧」，帧数 = 1 时默认落在「通道变换」——单帧图里看不到帧页在前台，但页签仍写着 `动画帧 (1)`。
5. **选中帧不影响导出**：批量导出遍历全部帧，选中第 3 帧导出与选中第 2 帧导出的帧条目逐字节一致。想只导一帧，用本页的「保存当前帧」。

## 更多示例

| 操作 | 输入 | 参数 | 观察 / 产物 |
|---|---|---|---|
| 保存中间帧 | 4 帧 APNG（4×3） | 连点两次下一帧 | `3 / 4 · 4×3` → `anim4.png_frame3.png`（113 B） |
| 反向回绕 | 同上，当前 1 / 4 | 点一次上一帧 | 标签变 `4 / 4 · 4×3` |
| 单帧图 | `single.png`（1 帧） | 直接打开帧浏览 | 标签 `1 / 1 · 4×3`，保存得 `single.png_frame1.png` |
| 0 帧 | 无图像描述符的 GIF | 打开 | 状态「打开失败：GIF 未包含可解码帧」，按钮禁用 |
