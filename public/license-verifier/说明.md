# 离线授权验证

将本目录完整保存，双击 `index.html`，或由静态 HTTP 服务打开。无需 Node、CDN、在线公钥或网络请求；需要支持 Web Crypto 的现代浏览器。HTTP 非回环且非 HTTPS 时，浏览器会限制 Web Crypto。

1. 通过恒烈独立可信渠道核对公钥指纹。页面默认嵌入现有 P-256 SPKI 公钥；`public-key.pem` 是同一公钥的下载副本。
2. 选择 `license.bin`，点击「验证签名」。文件 SHA256 以所选文件全部字节计算；原文 SHA256 以签名覆盖的解码后 payload 字节计算。
3. 自带公钥可粘贴 SPKI PEM/Base64 或选择文件。其指纹和「用户提供」状态会显示；成功只表示匹配该公钥。
4. 授权字段默认折叠，仅在本地展示。不要把授权文件、截图或字段内容自动上传到公共站点。

## 格式与显示

文件为 `base64url(payload原文UTF-8).base64url(signature)`，ECDSA P-256 / SHA-256，签名为 64 字节 IEEE-P1363 `r||s`。验签不重排或重新序列化 JSON。与 OpenPGP 包/证书/装甲格式不同，不能直接当 PGP 签名使用。

签名通过与展示有效分开。名字、图标、投喂码都在已签 payload 内；应用图标仅接受内嵌 PNG/JPEG：256 KiB / 1024×1024；投喂码为 1 MiB / 2048×2048。禁止 SVG、HTML、动画和远程图片；图片结构、预算或实际解码失败则隐藏/回退，不否定原签名。旧 `appName` 与 `ext` 保留，旧字段不自动重签。

## 公开与信任的边界

- 统一公钥可以公开；无法据此导出私钥或签发。公钥真实性取决于指纹的可信分发，而非「页面写了官方」或仅同站下载。公钥公开不等于逐授权内容公开。
- 现有 license.bin 的载荷只是 Base64 编码，不是加密；逐授权公开会暴露授权对象、备注、联系项、图像中的信息。仅公开文件/载荷哈希可做承诺，但旁观者没有原文就无法验签，也不能证明具体授权对象。低熵内容的哈希存在猜测关联风险。
- 若决定建立逐授权证明，应另行批准最小化公开 schema（随机许可 ID、用途、签发者密钥指纹、有效期、状态、必要授权摘要），征得对象同意并单独签署。不能删改现有 payload 后复用其签名。该工具不建立公开列表，不自动提交证明。
- 验签有效仅证明对应私钥签过这些字节；不证明现实身份、是否仍在授权期、撤销状态或声明内容真实。`issuedAt` 是签发者自述，不是可信时间戳；当前离线验证不检查有效期或撤销。
- 撤销需要单独签名的撤销清单及版本/更新时间和新鲜度策略。纯离线且无最新清单时不能证明「未撤销」。轮换需保留旧公钥验旧文件，通过独立可信渠道公告新指纹；旧钥交叉签署可辅助连续性，旧钥泄露时仍须独立身份渠道。
- ECDSA 是签名算法；OpenPGP 是含密钥/签名/身份认证等结构的体系。改成 PGP 不会自动解决身份核验、撤销新鲜度或法律效力，也会改变现有文件格式。现有密钥与算法保持。
- 签名提供密码学来源/完整性证据，不等于绝对法律不可否认性：密钥保管、多人共享、泄露时间、可信时间戳、主体识别和适用法律均影响举证。

统一公钥/工具的正式发布、逐授权证明范围、撤销与轮换政策，均由恒烈决定。此目录不包含真实授权样本、私钥或签发配置。
